# simpled

`simpled` sits between docker-compose and Kubernetes. It generates plain deployment
manifests from two files: `appspec.yaml` (what the application is) and `envspec.yaml`
or `localenv.yaml` (where it runs).

This skill was generated by `simpled init-agent` from simpled {{VERSION}}. The binary
carries its own documentation — always read it before editing a spec, rather than
guessing at field names.

## Read the documentation first

```bash
simpled docs agent          # condensed manual: mental model, rules, errors, gotchas
simpled docs                # list all topics
```

Then narrow down as needed:

```bash
simpled docs reference --outline               # every section heading
simpled docs reference --section secrets       # one section
simpled docs search "working_dir"              # locate a field across all topics
simpled docs tutorial                          # blank directory to running deployment
simpled docs examples                          # 10 annotated real-world configs
simpled docs cicd                              # GitHub Actions build and deploy
```

`simpled docs search` prints `topic#anchor` references; feed the anchor straight back
into `--section`.

## Workflow

1. **Before editing a spec**, read `simpled docs agent` and the relevant
   `simpled docs reference --section ...`.
2. **After editing `appspec.yaml`**, run `simpled app-bundle verify` from the app
   directory. It validates the spec and checks that the images exist.
3. **After editing an env spec**, run `simpled local generate-config` (for
   `localenv.yaml`) or `simpled prepare-deployment <name>` (for `envspec.yaml`) to
   validate the app and environment halves against each other.
4. **When a command fails**, look the message up in the "Error → fix" table in
   `simpled docs agent` before changing anything — most failures name the exact field.

## Rules worth remembering without a lookup

- The `name` in `appspec.yaml` must equal `application.name` in the env spec.
- `app_services` images carry **no** tag (the app version is appended);
  `extra_services` images **must** carry one.
- `host` in a deployment is a gateway host *alias*, mapped to a real domain under
  `gateway.hosts` — never a bare domain.
- Environment-specific values (domains, connection strings, replica counts) belong in
  the env spec. Structure (services, images, variable and secret *names*) belongs in
  `appspec.yaml`. Never put a secret value in `appspec.yaml`.
- `secrets_folder`, `working_dir`, and inline literal secret values are valid only for
  `type: local`.

## Do not

- Do not hand-edit anything under `k8s/`, `docker-deploy/`, or `local_env/` — those are
  generated and overwritten on the next run. Change the spec instead.
- Do not commit resolved secret values. Use `env:`, `file:`, or `aws:` sources.
