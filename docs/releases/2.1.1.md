On a multi_node Docker Swarm the gateway now runs on every node by default.

The swarm gateway publishes 80 and 443 in host mode, so it answers only on the nodes
running it. Until now a single unpinned gateway task could be rescheduled, after a
restart or a node loss, onto a node that DNS or the load balancer does not point at.

## Before you upgrade

- **`multi_node: true` (the default) without `gateway.global`:** the gateway becomes
  `deploy.mode: global`, one task per node. On a one-node swarm nothing changes. With
  more nodes, every node now answers on 80/443: keep nodes that should not take
  traffic out with a `gateway.placement` constraint or their security group.
- **`gateway.global: false`** now needs a `gateway.placement` constraint that pins the
  single task (e.g. `node.hostname == edge-1`); without one, validation fails.
- **`gateway.placement.preferences`** need `global: false`, as `preferences` cannot be
  combined with a global service.

`multi_node: false`, Kubernetes, `simpled local` and standalone Docker are unchanged.
