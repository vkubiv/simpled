simpled 2.0.0 makes Docker Swarm deployments safe to run on more than one node, and
lets several deployments share one swarm without stepping on each other. Kubernetes,
standalone Docker and `simpled local` generate what 1.13 did, apart from the gateway
changes below.

Most Swarm env specs need a few lines added before they prepare with 2.0.0. The
errors say what to add. [Upgrading to 2.0.0](https://github.com/vkubiv/simpled/blob/v2.0.0/docs/reference.md#upgrading-to-200)
walks through every case.

## Breaking changes

- **Swarm volumes are bound per volume.** Every named volume a Swarm deployment
  mounts needs a binding under `deployments.<name>.volumes`: `node` (a Docker volume
  on one node), `node` + `path`, `path` (a directory on every node) or `nfs`. A
  service follows its volumes, so a service with a `node` volume is pinned to that
  node. An unbound volume is an error that prints a block ready to paste.
- **No relative bind paths on Swarm.** `./data:/data` would mean a different
  directory on every node. Use a config for files a service only reads, or a bound
  volume for data it writes.
- **`multi_node`, default `true`.** Swarm specs are validated as if the swarm had
  several nodes, so a spec that works on one node keeps working when you add a
  second. `multi_node: false` keeps the 1.x behavior (unbound volumes, relative
  paths) and pins everything to the swarm's single node. `deploy.sh` then stops
  when more than one node accepts tasks.
- **`deploy.sh` runs a simpled binary next to it.** `prepare-deployment` writes
  `docker-deploy/simpled`, built for Linux amd64. Copy the whole `docker-deploy/`
  directory to the target as before. Targets on another CPU set
  `target_platform: linux-arm64`, and, until releases include that binary, pass
  `--target-binary`.
- **Only Traefik on Docker.** `gateway.type: nginx` and `gateway.tls.secret` on
  Docker are errors. Use `tls.letsencrypt`, or `tls.upstream: true` when TLS ends in
  front of the gateway.

## Docker Swarm

- **Configs and secrets are Swarm objects.** They are no longer bind-mounted from
  the deploy directory, so every node has them. Each object is named after a hash
  of its content, so changing one is an ordinary deploy, and `docker service
  rollback` still finds the previous one. A config or secret holds at most 500 KB.
- **Deploys restart only what changed.** Services no longer carry `DEPLOY_DATE`, so a
  service restarts only when its image, environment, configs or secrets change. The
  gateway restarts when its routing changes.
- **Several deployments in one env spec.** A deploy takes a swarm-wide lock, and
  another one waits for it (`SIMPLED_LOCK_WAIT`, default 10 minutes). Before
  replacing the shared gateway, the deploy refuses to put back an older simpled's
  gateway, and prints the routes it changes, so a deploy from a stale checkout
  shows up in the log. Give each deployment its own directory on the target.
- **Readable steps.** `deploy.sh` still lists every step. The hard ones are now
  `./simpled step ...` commands: lock, node check, syncing and pruning objects,
  running jobs, and the gateway check.

## Known limitations

- Traefik's Let's Encrypt store (`letsencrypt/acme.json`) is still a bind mount of
  the deploy directory, on the manager that runs `deploy.sh`. On a swarm of several
  nodes, pin the gateway to that node with `gateway.placement`.
- Releases do not include a Linux arm64 binary yet, so arm64 targets need
  `--target-binary`.
- A deployment removed from the env spec keeps its stack running; remove it with
  `docker stack rm <deployment>`.

## Before you update

`simpled update`, and CI steps that install the latest release, move to 2.0.0. Pin
1.13.1 in CI until your Swarm env specs are updated.
