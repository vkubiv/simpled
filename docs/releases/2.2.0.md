simpled 2.2.0 adds a gateway access log on Docker, and changes what the controller's
health routes answer with: the HTTP status now says whether the controller works, and
the health itself is only in the body.

## Before you upgrade

- **`/simpled/health` and `/simpled/health/<deployment>` answer 200 even when
  `degraded` or `down`.** Until now anything but `healthy` was a 503, so a rolling
  update, an expiring certificate or one broken side app made the whole environment
  look unavailable to clients, proxies and balancers. A 503 now means only that the
  controller cannot read Docker (or, for `/simpled/health`, the gateway service), still
  with whatever document it could build. An uptime check that alarmed on the status
  code alone now hears only about the controller itself: match `"status":"healthy"` in
  the body of `/simpled/health/<deployment>`, or read the JSON.

  `simpled wait` reads the body whatever the status, so it works against 2.1 and 2.2
  controllers alike. Kubernetes and `simpled local` are unchanged.

## Gateway access log

- **`gateway.access_log: true`** (Docker only) has Traefik log one line per request,
  for every host and app, on the gateway's stdout next to its own log. It is read
  with `docker service logs simpled_gateway`, `docker logs simpled-gateway` or
  `simpled logs`, and a log driver or agent ships it on, e.g. to CloudWatch Logs.

  ```yaml
  gateway:
    access_log: true                # JSON
    # access_log: {format: common}  # Common Log Format
  ```

- A JSON line carries the client IP (`ClientHost`), `RequestHost`, `RequestPath`,
  `RouterName` and `ServiceName` (which app), `DownstreamStatus`, `Duration` and
  `request_X-Forwarded-For`. Every other request header, cookies and authorization
  included, is left out.
- The client IP is the original client's only when the request comes from a
  [`trusted_proxies`](../reference.md#trusted_proxies) address; from any other, Traefik
  drops `X-Forwarded-For`, so it cannot fake the IP.
- Unset or `false`, the gateway config is what it was. Rejected on Kubernetes (the
  ingress controller owns its access log) and `simpled local`.
