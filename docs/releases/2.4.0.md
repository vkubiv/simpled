simpled 2.4.0 gives every Docker deployment a network of its own, connects
deployments only over networks the env spec declares, and adds the gateway's log to
`simpled logs`.

## A network per deployment

- **Isolated by default** (Swarm and standalone): each deployment runs on
  `simpled-<deployment>` instead of the shared `common_network`. A bare name
  (`redis:6379`) always resolves inside the asking deployment; another deployment's
  service is `<deployment>_<service>`, reachable only over a shared network.
- **`networks:`** at the top level declares the shared networks, and a deployment's
  `networks:` joins them, with every service (a list) or the named ones (a map):

  ```yaml
  networks:
    app1-db:
    app2-db:
  deployments:
    prod_db:
      networks:
        app1-db: [postgres]
        app2-db: [postgres]
    prod_app1:
      networks: [app1-db]
    prod_app2:
      networks: [app2-db]
  ```

  `prod_app1` and `prod_app2` reach `prod_db`, not each other. Joining is part of a
  deployment, so a deployment added to a network means redeploying the ones already
  on it. See [networks](../reference.md#networks).
- On Swarm, `docker stack deploy` also puts bare names on shared networks: a bare
  name a deployment does not have itself can resolve across one. Use
  `<deployment>_<service>` across networks.

## Upgrading

- Two deployments that call each other today over `common_network` must join a
  declared network, and address each other as `<deployment>_<service>`.
- Each deployment moves to its own network on its first 2.4 deploy. The gateway stays
  on `common_network` too, so deployments not yet redeployed are still routed.
- Standalone Docker names containers `<deployment>_<service>` instead of `<service>`.
  The first deploy removes the old container, which held the service's host ports.

## Gateway logs

- **`simpled logs gateway`** prints the gateway's log, with the options of a
  service's (`-f`, `--tail`, `--since`, `--timestamps`): Traefik's own lines and, with
  `gateway.access_log`, one per request. Served by the controller at
  `GET /simpled/api/v1/gateway/logs`, so it needs the 2.4 controller, which a 2.4
  deploy rolls out.
